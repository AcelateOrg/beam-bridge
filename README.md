# BeamBridge

Общее ядро VPN-клиента BEAM. Здесь живёт вся логика, которая не зависит от
интерфейса: профили, подписки, формат `.beam`, маршрутизация, сборка конфига
сетевого ядра, запуск ядра и TUN, статистика. Десктоп и Android остаются
тонкими оболочками вокруг него, поэтому оба клиента ведут себя одинаково.

```
                     beam-bridge
     типы · настройки · профили · подписки · VPN
            │                         │
       beam-core                  beam-tun
    (форк Xray-core)       (TUN, маршруты, kill switch)

   beam-desktop (Wails + React)    beam-mobile (Android, через gomobile)
```

## Как это работает

1. Оболочка вызывает конструкторы ядра и передаёт им пути и сведения о среде.
2. Ядро хранит профили и настройки на диске, обновляет подписки и собирает из
   выбранного профиля конфиг для beam-core.
3. `core/runner` поднимает beam-core, TUN-адаптер из beam-tun (или системный
   прокси) и следит за их жизненным циклом.
4. Статус, статистика и ошибки уходят обратно в оболочку через события.

## Структура

```
core/
  types/            общий словарь: профили, узлы, статусы, граф ProTun
  paths/            раскладка каталогов, передаётся явным параметром
  platform/         сведения о среде: крэш-логи, версия ОС, локаль
  domain/settings/  структуры настроек и интерфейс репозитория
  infrastructure/
    beam/           формат .beam: чтение, запись, шифрование, миграции
    subscription/   парсеры подписок: VLESS, VMess, Trojan, Shadowsocks,
                    Hysteria2, JSON-конфиги
    persistence/    хранилища профилей и настроек на диске
    mediacache/     кэш картинок провайдера (иконка, баннер)
  profile/          менеджер профилей, сборка конфига ядра, задержка узлов
  coreapi/          единственная точка доступа к beam-core
  xray/             запуск ядра, статистика, соединения, логи
  runner/           жизненный цикл: ядро + TUN + системный прокси
  sysproxy/         системный прокси Windows / Linux / macOS
  probe/            замер задержки так, как её чувствует пользователь
  analytics/        локальная статистика трафика
  geodata/          geoip / geosite
  vpn/              статус-машина соединения и статистика

mobile/             API для Android (gomobile bind → beam-bridge.aar)
cmd/                служебные утилиты (beamlink, xrayprobe)
docs/               заметки по формату ссылок, баннерам, производительности
```

## Что ядро получает от оболочки

- **Пути** (`core/paths`) передаются явным параметром в конструкторы. Глобальных
  значений по умолчанию нет: ошибка в путях ловится компилятором, а не уводит
  ядро писать в чужой каталог.
- **Сведения о среде** (`core/platform`) ставятся переменными-функциями:
  крэш-логи, версия приложения и ОС, локаль, список процессов.
- **События** ядро наружу само не шлёт: `vpn.Manager.SetEmitter` принимает
  функцию. Десктоп подставляет `runtime.EventsEmit` из Wails. События:
  `vpn:status`, `vpn:stats`, `vpn:error`.

## Сборка

Обычный Go-модуль (Go 1.26). Рядом в одной папке должны лежать
[`xray-core-beam`](https://github.com/AcelateOrg/xray-core-beam) и [`beam-tun`](https://github.com/AcelateOrg/beam-tun): они
подключены через `replace` в `go.mod`.

```bash
make check      # build + vet + тесты
```

Пакет `mobile/` собирается только под Android (`//go:build linux` и Android API),
поэтому на Windows `go build ./...` в нём падает. Это ожидаемо. AAR для
приложения собирает скрипт `beam-mobile/scripts/build-bridge.ps1`.
